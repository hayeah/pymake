# User Task

Implement the Input contract per `docs/input-contract-design.md`: unify
staleness under "every dependency is an input with a fingerprint", with
the executor owning comparison and recording. Retire the `run_if` /
`TreeDigest` commit side-protocol (deprecation warnings, not breakage);
existing Makefiles must keep working at every commit.

# What shipped

- `src/pymake/inputs.py` — the `Input` protocol (`id` + `fingerprint()`),
  `value(id, x)`, `git(id, repo, ref=None, paths=[...])`, definition-site
  capture (one inspect hop), capability-based detection (`is_input`).
- `src/pymake/state.py` — per-task JSON records under `.pymake/state/`
  (kind-partitioned paths/deps/inputs + flip counters), atomic
  temp+rename writes, versioned format (mismatch reads as no-record).
- `src/pymake/staleness.py` — fingerprint computation: `mtime_ns:size`
  paths, dep-outputs contribution, per-run memoization by input id
  (`FingerprintCache`), record diffs with reason wording.
- `executor.py` — the single rule `run = cli_force or
  fingerprints_changed or outputs_missing or no_record`; decision lines
  with reasons; post-run fresh re-walk + recording; bootstrap migration
  for legacy tasks; inline divergence warning (git dirt sample) and
  flip-counter nondeterminism warning (N=3).
- `task.py` — inputs partitioned into three namespaces; id enforcement at
  registration (missing/empty id, duplicate id names both definition
  sites); `run_if`/`run_if_not` deprecation (FutureWarning);
  severed-wrapper hard warning (UserWarning) via
  `digest.severed_commit_wrapper`.
- `doctor.py` — `sweep=True` (doctor command only): flip-counter
  aggregation + severed-wrapper scan; `check_before_run` now blocks on
  errors only.
- `tree_digest()` factory warns FutureWarning; `TreeDigest` class itself
  stays silent (internal/test use).
- Docs: SKILL.md (Input contract section, new execution semantics,
  deprecation notes), REPOMAP, and an "As implemented" appendix in the
  spec listing every deviation.

# Deviations from the spec (full list in the spec's appendix)

- `git` with `paths=` fingerprints the scoped tree hashes ONLY (no commit
  id) — including the commit would retrigger on unrelated commits and
  defeat the scope. Pathspec magic (`:(glob)`) falls back to
  `git log -1 --format=%H <commit> -- <pathspec>`.
- Legacy carve-outs for compatibility: phony-always-run for tasks without
  Input objects; one-time mtime fallback + record bootstrap when a legacy
  task has no record; outputs-only tasks never record.
- `touch=` does NOT deprecation-warn (spec's compat section said it
  should): for legacy path-input tasks it remains the only output marker,
  so there is no replacement to point at short of adopting Inputs.
- Divergence "sample files" exist for paths (the name is the file) and
  git inputs (up to 3 porcelain rows, re-scanned at warn time); value and
  custom inputs have none.
- Severed-wrapper detection is one hop: closures, referenced module
  globals, partials, argument defaults, bound-instance attributes.
  Deeper indirection is not detected (documented in the docstring).
- `run_if` ordering (staleness first) is preserved, trap included — it is
  deprecated wholesale rather than reordered.

# Known gaps

- `pymake which` and dry-run plans still mark would-run via the legacy
  mtime heuristic; fingerprint decisions show only in executor decision
  lines.
- "State format v2 — full rebuild" loud-invalidation banner: still an
  open question; version mismatch silently reads as no-record (task
  re-runs, which is the safe direction).
- Submodule pointers as dirt: undecided (open question in the spec).
